🏗️ Pillar 9 — Infrastructure
Terraform-managed deployments, compute governance, and optimization
Infrastructure-as-Code First All MRx infrastructure is defined, versioned, and deployed exclusively via Terraform. No manual Azure portal changes are permitted in staging or production environments. Every resource is created from code — ensuring full reproducibility and auditability.
🌍
Terraform IaC
  • All infrastructure provisioned via Terraform — Databricks workspaces, Unity Catalog, network, and storage managed as IaC in Git
  • Modular architecture: reusable modules for each Azure service type
  • Internal module registry enforcing approved patterns
  • Terraform plans reviewed as part of PR checks before apply
  • Drift detection: scheduled terraform plan runs detect manual changes
  • State locking prevents concurrent modifications
  • Workspace-per-environment isolation: dev / staging / prod state files separate

🔧 Pillar 8 — Ops Readiness Framework
Change management, incident management, compliance, and service integration
Production Readiness Gate Before any new service or pipeline is promoted to production, it must pass the MRx CoE Ops Readiness Review — a cross-functional review ensuring operational, compliance, and support requirements are met before go-live.
📝
Change Management
  • All production changes submitted as RFCs in ServiceNow
  • Change types: Standard (pre-approved), Normal (reviewed), Emergency
  • CAB approval for Tier-1 pipeline changes — weekly CAB meeting
  • Automated CR creation triggered by GitHub Actions on prod deploy
  • Post-implementation review (PIR) mandatory for Normal and Emergency changes
  • Change success rate and MTTR tracked on monthly ops dashboard

  • Runbooks linked to each incident template in ServiceNow

  • Blameless post-mortems within 5 business days of P1/P2 closure

💰 Pillar 10 — Cost Avoidance & FinOps
FinOps practices, cost monitoring, and optimization strategies
Target KPI Achieve 20% year-on-year unit cost reduction per DBU consumed through optimization, caching, and right-sizing initiatives. Cost is a first-class engineering concern — tracked alongside reliability and quality.
📊
FinOps Monitoring
  • Azure Cost Management + Billing — primary FinOps tooling for Azure spend
  • Databricks Cost Dashboard — DBU consumption tracking per workspace and cluster
  • Weekly cost reports by team, workspace, and cluster
  • Cost anomaly detection: >20% week-on-week increase triggers review
  • Budget alerts at 80% and 100% of monthly target
  • Monthly FinOps review embedded in ops review meeting agenda
Azure Cost MgmtFinOps
🎯
Chargeback Model
  • DBU consumption and storage costs allocated to business units via CostCenter tagging
  • Monthly showback reports distributed to domain owners
  • Chargeback model drives accountability — teams own their cost consumption
  • Infracost integrated into GitHub Actions to show per-PR infrastructure cost delta
  • New workloads require cost estimate sign-off before provisioning
ChargebackInfracost
📉
Waste Elimination
  • Orphaned clusters, unused volumes, and stale checkpoints identified weekly via automation
  • Removal requires owner confirmation to prevent accidental deletion
  • Storage tiering: Hot → Cool → Archive based on access frequency
  • Lifecycle policies automated — estimated 40% storage cost reduction
  • Quarterly unused resource audit with mandatory cleanup sprint

📊 Pillar 11 — Platform Observability
Monitoring, dashboards, and alerting across the data platform
Observability Stack MRx uses Grafana for unified dashboards and Azure Monitor for infrastructure-level metrics and log analytics — providing a complete view of platform health from cluster uptime through to data pipeline SLA compliance.
📈
Grafana Dashboards

Unified monitoring dashboards with role-based access — all dashboards version-controlled as JSON in Git:

  • Pipeline Health: cluster uptime, job success rate, API latency, storage capacity
  • Pipeline SLA: per-pipeline compliance (target latency vs actual)
  • Data Quality: DQ rule pass/fail rates, anomaly trends over time
  • Cost Dashboard: DBU consumption, Azure spend, cost-per-pipeline
  • Security Dashboard: alert trend, open findings by severity, posture score
  • Incident Dashboard: open incidents by priority, MTTR trends
GrafanaGitOpsRBAC Access

Azure Monitor
  • Infrastructure-level monitoring: ADF pipeline runs, Databricks job metrics, storage latency, network throughput, VM health
  • Log Analytics Workspace: centralised log aggregation — unified KQL query interface across Databricks, ADF, storage, and application logs
  • Alert rules: tiered alerts — pipeline failure, SLA breach, cost threshold, security anomaly
  • Routed to Slack, email, and PagerDuty by severity
  • Application Insights: APM for REST APIs deployed alongside pipelines
  • Custom metrics published from Databricks jobs via Azure Monitor REST API
