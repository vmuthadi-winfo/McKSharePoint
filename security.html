🛡️ Security Overview
Defence-in-depth security architecture protecting the MRx platform at every layer
Security Posture MRx operates a zero-trust, defence-in-depth security model. Security controls are enforced at the network, identity, data, application, and CI/CD pipeline layers — ensuring that compromise at any single layer does not result in data exfiltration or platform disruption.

Identity & Access Control
  • Azure Active Directory (Entra ID) — centralised identity provider for all MRx services
  • Managed Identity (MSI) for all service-to-service authentication — no stored credentials
  • Role-Based Access Control (RBAC) enforced at Azure resource level
  • Databricks Unity Catalog — row/column-level security for data access
  • Privileged Identity Management (PIM) — just-in-time elevated access
  • Quarterly access reviews — stale permissions removed automatically
  • Multi-Factor Authentication (MFA) mandatory for all human accounts
Entra IDPIMRBAC
🌐
Network Security
  • All Databricks workspaces deployed in VNet injection (no public egress)
  • Private endpoints for ADLS Gen2, Key Vault, Azure Container Registry
  • Network Security Groups (NSG) with deny-all default + explicit allow rules
  • Azure Firewall with FQDN-based outbound allowlisting
  • No public IP addresses on data compute nodes
  • DDoS Protection Standard enabled on production virtual networks
  • Network traffic flow logs captured to Log Analytics for forensic investigation
VNetPrivate EndpointsNSG
🗝️
Secrets & Key Management
  • Azure Key Vault — centralised secret, key, and certificate management
  • Databricks Secret Scopes backed by Key Vault — no secrets in notebooks or code
  • Key rotation policy: credentials rotated every 90 days automatically
  • Key Vault access restricted to MSI only — no key vault access policies for humans
  • Soft-delete and purge protection enabled on all production Key Vaults
  • Certificate expiry monitoring: alerts raised 30 days before expiration
  • GitHub Secrets for CI/CD credentials — never hardcoded in workflow files

🔎 Vulnerability Management
Panorama integration and systematic vulnerability tracking, triage, and remediation
📡
Panorama Integration

MRx vulnerability findings are centrally managed through the McKinsey Panorama vulnerability management platform:

  • Wiz and GitHub Security findings auto-ingested into Panorama via API connectors
  • Findings deduplicated and correlated across multiple scanners in Panorama
  • CVE enrichment: CVSS scores, exploit availability, and asset criticality weighting
  • Risk-based prioritisation: findings ranked by exploitability × asset sensitivity
  • Panorama ticket auto-assigned to the responsible engineering team
  • SLA tracking: Critical (5 days), High (30 days), Medium (90 days)
  • Metrics dashboard: open findings by severity, age, and team ownership
  • Monthly vulnerability posture report distributed to Tech Lead and CISO

☁️ Wiz Cloud Security Monitoring
Cloud Security Posture Management (CSPM) and Cloud Workload Protection (CWPP) via Wiz
Wiz Deployment Scope Wiz is deployed across all MRx Azure subscriptions with agentless scanning. It continuously assesses the security posture of every Azure resource, container image, and Kubernetes workload — providing a real-time risk graph of the entire MRx platform.
🔭
Wiz CSPM — Cloud Security Posture
  • Continuous misconfiguration scanning across all Azure resources (storage, network, identity)
  • Checks against CIS Azure Benchmarks, NIST CSF, and McKinsey internal security policy
  • Publicly exposed storage accounts or VMs → Critical finding, immediate alert
  • Overly permissive IAM roles detected and flagged for remediation
  • Encryption-at-rest compliance: unencrypted disks flagged as High severity
  • MFA enforcement check on all human identity accounts
  • Wiz Security Graph: visual risk path from internet-exposed resource to sensitive data
  • New resources scanned within minutes of provisioning
CSPMCIS BenchmarkWiz
🐳
Wiz CWPP — Workload Protection
  • Container image scanning in Azure Container Registry — vulnerabilities detected before deployment
  • Kubernetes (AKS) workload assessment: pod security, privileged containers, host path mounts
  • OS vulnerability scanning: known CVEs in cluster node operating systems
  • Runtime threat detection: anomalous process execution, suspicious network calls
  • Databricks cluster node vulnerability assessment via Wiz agentless scan
  • Secrets in environment variables or container filesystems detected and alerted
  • Software Bill of Materials (SBOM) generated for all deployed container images

🔍 GitHub Security Scanner
GitHub Advanced Security — secret scanning, code scanning (SAST), and dependency review
GitHub Advanced Security (GHAS) All MRx repositories have GitHub Advanced Security enabled. GHAS provides three core security capabilities integrated directly into the developer workflow: secret scanning (prevents credential leakage), code scanning / CodeQL SAST (detects vulnerabilities at commit time), and dependency review (blocks vulnerable package additions).
🔑
Secret Scanning
  • GitHub Secret Scanning enabled on all MRx repositories (push and historical scan)
  • Detects: API keys, connection strings, certificates, Azure SAS tokens, PATs, OAuth tokens
  • Custom patterns configured for McKinsey-specific credential formats
  • Push protection: blocks commits containing detected secrets before they reach the repository
  • Secret alerts routed to Security team inbox in addition to repository owner
  • Detected secrets are treated as compromised and rotated within 1 hour (P1 response)
  • False positive bypass requires written justification and Security team approval
Secret ScanningPush Protection
🔬
Code Scanning (CodeQL SAST)
  • CodeQL static analysis scans all MRx repositories on every PR and push to main
  • Languages covered: Python, JavaScript/TypeScript, SQL (HCL via 3rd-party action)
  • Detects: SQL injection, XSS, path traversal, insecure deserialization, SSRF
  • Custom CodeQL queries written for MRx-specific security anti-patterns
  • Required status check: CodeQL must pass before PR can be merged
  • Code scanning alerts exported to Panorama via GitHub API connector
  • Severity-based merge blocking: Critical and High alerts block merge
CodeQLSASTRequired Check
📦
Dependency Review & Dependabot
  • Dependency Review Action runs on every PR — blocks merging of vulnerable packages
  • Checks for known CVEs in: Python (pip), Node.js (npm), Terraform (Hashicorp), Docker base images
  • Dependabot: automated PRs to update vulnerable dependencies within 24 hours
  • Dependabot security updates auto-merged if CI passes and CVSS < 7.0
  • High/Critical Dependabot alerts assigned to on-call engineer for expedited review
  • Software Composition Analysis (SCA) reports included in monthly security dashboard
DependabotSCADep Review

Security in CICD Pipeline

  • GHAS results surfaced inline in PR diff view for developer awareness

  • Terraform security scanning via tfsec / checkov in IaC PR pipeline
  • Container image scanning via trivy action before ACR push

🔔 Monitoring & Alerting for Compromised Data
Detection, response, and containment processes for data security incidents
Data Security Incident Response MRx maintains a dedicated Data Security Incident Response Plan (DSIRP) covering detection of data exfiltration, unauthorised access, and data compromise events. The plan integrates with McKinsey's enterprise Security Operations Centre (SOC) for co-ordinated response.
👁️
Data Exfiltration Detection
  • Azure Defender for Storage: anomalous access pattern detection (volume, geo, time)
  • Unity Catalog audit logs: all data access events logged to Log Analytics
  • Databricks IP access lists: connections from unexpected IPs trigger alert
  • DLP (Data Loss Prevention): Sensitive data classification via Azure Purview / Microsoft Purview
  • Outbound data transfer volume monitoring: alert on bulk export exceeding threshold
  • Unusual service principal access patterns detected via Azure Sentinel analytics rules
  • Azure Sentinel UEBA (User Entity Behaviour Analytics) detects insider threat patterns
Azure SentinelDLPUEBA
🚨
Security Alerting & Escalation
  • Azure Sentinel SIEM: centralised security alert correlation and triage
  • Analytic rules: 50+ custom rules tuned for MRx-specific threat scenarios
  • Alert severity mapping: Informational → Low → Medium → High → Critical
  • P1 Security Alerts: immediate PagerDuty page to Security on-call + Platform Lead
  • Automated playbooks (Azure Logic Apps): IP block, token revocation, cluster suspension
  • Escalation to McKinsey SOC for confirmed data breach events within 15 minutes
  • GDPR / CCPA notification obligations tracked: 72-hour breach notification window
